# Make something worth sharing.

You do not need permission to bring a good question. Suggest a tool you wish were
free, investigate a workflow, improve a specification, design an interface, or work a ticket.

## Start with a useful workflow

Tell us who depends on the software, what they need to do, and where existing free
software falls short. Share sources. If an existing project is already close, helping
that project may be the most generous thing we can do.

[Suggest software on GitHub](https://github.com/508-dev/genairosity/issues/new?template=nomination.yml)

## Pick a ticket. Work your way.

Find a bounded task, check its prerequisites, and leave a comment before starting.
Work by hand or use your preferred local tools. Codex, Claude, OpenCode, Paseo, and
other harnesses are options, not requirements. You start and control any model session.

Bring back a pull request with the issue link, what changed, and evidence that it works.
Research contributions can be documents and findings. Implementation follows a reviewed
specification. Maintainers review before merging.

[Read the contributor guide](https://github.com/508-dev/genairosity/blob/main/CONTRIBUTING.md)

## Establish a project

Accepted ideas get a small, stack-neutral starter: a charter, source records,
specification, work templates, and a local conformance checker. A maintainer activates
a project by registering its repository in the hub. Acceptance does not promise a
schedule or a complete replacement for the reference application.

[Use the project devkit](https://github.com/508-dev/genairosity/blob/main/docs/project-setup.md)

## Freedom includes your tools

AI can make ambitious software development more feasible. Human judgment, research,
design, testing, and manual implementation belong here just as much. No hosted model
runner assigns work or spends your tokens. No project has to be profitable to be worthwhile.
