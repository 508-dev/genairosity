# Contributing

Work manually or use any locally initiated harness. Read the charter and research
policy, then choose an issue with an objective, prerequisites, bounded scope,
acceptance criteria, and a verification method. Comment before starting to coordinate.

Research can produce documents. Implementation requires a maintainer-approved
specification tied to a commit and recorded in genairosity.json. Use original code
and permitted FOSS dependencies; preserve notices and source evidence. Uncertain
inputs need review, not a guess.

Create a branch and submit a PR linking the issue, describing the change and actual
verification results. Run python3 scripts/check-project.py and the checks in
docs/verification.md. A maintainer reviews and merges. Claims are coordination,
not permanent ownership of a task; communicate delays and blockers.

Contributions use the repository license. No copyright assignment is required.
Keep discussion respectful. Never publish secrets or proprietary material. Before
a usable release the maintainer must document a private security-reporting route.
